## リスクレベル判定結果

**判定: レベルC**

### 判定根拠

- 変更内容: gRPCエラーオブジェクト（grpcCode/message/method/requestキーを持つがErrorインスタンスではないもの）をSentryで適切にキャプチャできるようにする改善（beforeSendフック導入 / gRPCクライアントラッパー作成 / 発生源調査 等）
- 該当基準: 「監視・ログ・エラーハンドリング（通知含む）の変更」「意図しないログ出力の変更」（C/D境界の観点）
- jobmatching-web全体のエラーハンドリングに横断的に影響する可能性があり、Sentryでのエラーグルーピング・通知挙動が変化する
- 応募・選考・メッセージ・企業管理画面などの主要導線のデータ処理ロジックには変更なし、流通高への直接影響もなし
- 「意図的に出力しているログの欠損」（レベルB）には該当しない想定（むしろキャプチャを改善する方向）

### 必要な対応

| 項目 | 要否 | 備考 |
| :--- | :--- | :--- |
| 開発承認者 | テックリード または 募集部GM | |
| リリース手順（リバート含む）の事前記載 | 推奨 | Sentryのエラー検知挙動が変わるため、リリース後の監視も推奨 |
| #released チャンネル投稿 | 推奨 | 監視・エラーハンドリングの変更点として共有することを推奨 |

### 不確実性・確認事項

- 実装方針（beforeSendフック / gRPCクライアントラッパー / 発生源修正）によって影響範囲が変わる。クライアントラッパー方式の場合は全gRPC呼び出しに横断的に影響するため、状況によってはB寄りでの再評価が必要
- 既存のConnectError等の正常系エラーフローに副作用がないか（誤ってフィルタ・変換してしまわないか）の確認が必要
- Sentryのエラーグルーピングが変化することで、既存アラート・ダッシュボードの感度が変わる可能性。関連メンバーへの事前共有が望ましい
- 本判定はIssue段階のため、実装PRが出た時点で差分内容を踏まえて再判定することを推奨
